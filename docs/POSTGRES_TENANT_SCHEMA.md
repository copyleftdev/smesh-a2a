# PostgreSQL schema-v6 durable authority

The executable PostgreSQL authority is implemented by `PostgresTaskStore`; revision 1 is the logical schema-v6 baseline, `0002_quota_reservation_seam.sql` adds the PostgreSQL-only atomic quota reservation seam, `0003_receiver_sender_fence.sql` adds the receiver sender fence, and `0004_distributed_quota_authority.sql` adds the distributed quota ledger. None changes SQLite v6. The older `reference/postgres_v2_logical_schema.sql` is retained only as historical design input and must not be applied.

## Physical parity

The migrations create the 18 authority tables plus `schema_migrations`. Canonical JSON is stored as validated `TEXT`, timestamps are signed `BIGINT` milliseconds, cryptographic cursor/receipt keys are 32-byte `BYTEA`, and idempotency remains keyed by `(tenant_scope,message_id)`. Tenant-leading composite keys, foreign keys, immutable-identity triggers, append-only audit triggers, bounded checks, and the eight list query-family indexes are installed transactionally.

`PostgresTaskStore::open` accepts distinct migrator and runtime URLs, validates both before acquisition, takes a transaction-scoped advisory migration lock, applies the baseline atomically, and verifies a migration checksum plus a persisted manifest over relations, exact columns/types/defaults, constraints, indexes, trigger/function bodies, policies, grants, role attributes, and membership. It also scans complete task-event chains (sequence, revision, transitions, typed JSON and current-row equality), task identities/state/timestamps, payload and frame digests, transcript seals, and frozen-snapshot metadata before opening a bounded runtime-only pool. The migrator connection is dropped before the pool is built. Reopen preserves key/store identity. Unexpected or mutated managed catalog or semantic state blocks startup.

Live mutations use trigger-maintained tenant/account/principal retained-byte counters under scoped row locks; they never take the global quota advisory lock or run the full authority oracle. The hard 64 MiB default and policy-specific retained limits are enforced transactionally by those counters, while startup/admin verification independently scans every tenant-bearing table (including taskless quota evidence). Revision 4 adds immutable policy snapshots and intent groups, separate fixed-window/gauge buckets, continuous integer token buckets with durable available-token/refill-remainder/database-time state, per-charge receipts, active-work allocations, fenced expiring stream/subscription leases, execution reservations, exact-idempotent digest-only denial evidence, and digest-only static override audit. Initial admission and continuations reserve output/event maxima atomically at tenant and principal scopes before outbox claiming. Private reservation identity/version, policy binding, and strict budgets are immutable on outbox/receiver rows and sender/receiver leases. Receiver completion stores canonical per-event UTF-8 measurement before effects or frames; terminal task/outbox triggers and sender reconciliation charge actual use and refund unused capacity once. Public-egress replay charging remains a separate operation and is not reused as execution settlement. All tables have tenant-leading keys, forced RLS, least runtime grants, and catalog validation. Exact workflow replay verifies the original stored intent/reservation while a separate current-policy request intent charges each invocation's request/input units. A task-state trigger releases active work and settles execution reservations exactly once on terminal, `InputRequired`, or `AuthRequired` transitions. Stream/subscription slots renew with DB-time fencing and release/reclaim capacity exactly once. The older singular `QuotaReservationInput` remains compatibility-only when distributed enforcement is disabled. SQLite rejects quota-bearing commands and remains schema v6.

The required `SMESH_A2A_QUOTA_POLICY_PATH` is loaded before PostgreSQL production startup. Its strict schema rejects unknown/duplicate/fractional/zero/overflowing values and hard-cap violations. Tenant/account/principal identities and the semantic binding are server-derived; request metadata and caller clocks cannot alter limits or override state. Static overrides are exact-scope/exact-operation/exact-dimension, bounded, half-open in database milliseconds, policy-revisioned, and persisted digest-only before use. Frozen pages persist projected task JSON, revisions, order, total, metadata HMACs, and only SHA-256 hashes of HMAC-derived opaque page capabilities; page replay remains fixed across task mutation and process restart.

Revision 4 additionally materializes exact tenant/account/principal retained UTF-8 JSON bytes, records generated evidence retention boundaries, and installs bounded child-first quota GC. Task-bound evidence remains live because the durable task/idempotency chain has no deletion contract. Higher policy revisions are reconciled under a second startup-only advisory fence: lower limits require an exact digest-bound `drain` plan, usage above the new limit returns `ReconciliationRequired` without mutation, and successful migration carries only mathematically valid consumptive fixed-window/token state. Gauge buckets and refundable task output/event buckets are never copied: current-policy admission derives cross-version live allocations, nonexpired leases, and unsettled reservations from their authoritative rows, while old completion releases or settles only the original policy bucket. The old policy becomes `draining`; its receipts, reservations, allocations, buckets, replay, settlement, and GC references remain addressable until the retention horizon and dependency checks permit collection. Startup validates retained counters against a full all-table/taskless oracle, evidence links, execution/lease semantics, and reconciliation seals.

Outbox fairness uses one retained, forced-RLS scheduler row per tenant, ordered by `(virtual_finish, served_sequence, tenant_scope)`. Claims lock only one eligible tenant row with `FOR UPDATE SKIP LOCKED`, then claim that tenant's oldest due outbox row in the same transaction. A PostgreSQL sequence supplies monotonic service order without a singleton row or advisory lock; claim, cursor advancement, and attempt insertion commit or roll back atomically. Expired quota leases are reclaimed in one validated `1..=1000` ordered `SKIP LOCKED` batch per operation, so maintenance cannot scan or update every expired lease at once.

## Security and roles

The migration creates a schema-specific `NOLOGIN NOINHERIT NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE NOREPLICATION` group role. It grants the bounded runtime login exactly one non-admin, non-inheriting membership with only `SET ROLE`; PostgreSQL records the non-superuser migrator that created the role with the exact admin/non-inherit/non-set membership needed to retire it. Startup recursively inspects `pg_auth_members` before first migration and after catalog sealing, rejects cycles, nested or unexpected memberships, membership-option drift, and any reachable login/superuser/BYPASSRLS/CREATEROLE/CREATEDB/REPLICATION capability. Every tenant-bearing table has `ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY`; policies compare `tenant_scope` with `current_setting('smesh.tenant_scope', true)`. Runtime transactions use `SET LOCAL ROLE` and bound `set_config(..., true)`, so missing context fails closed and transaction-pool reuse cannot retain context. Global claiming, cancellation polling and diagnostics are fixed-`search_path` `SECURITY DEFINER` procedures returning only one claim, one boolean, or aggregate counts; the runtime login never receives global table visibility.

Production URLs must require TLS. Plaintext is accepted only by the explicit test-only loopback switch used by the real PostgreSQL fixture. URLs and passwords are never formatted into adapter errors or `Debug` output.

Production outbox and receiver claims, renewals, finishes, deliveries, completions, and cancellation/lease arbitration derive the effective milliseconds from `db_millis()` inside the same transaction; caller clocks cannot extend or prematurely invalidate a fence. The explicit loopback-only deterministic test seam retains injected command times so the SQLite/PostgreSQL conformance fixture can compare exact records. PostgreSQL advertises required lease renewal capability and fully fences renewal by tenant, durable identity, owner, token, attempt/epoch, prior expiry, state, and database time. SQLite explicitly advertises unsupported renewal and retains exclusive-process behavior.

## Operations runbook

1. Provision PostgreSQL 17 (HA, replication, WAL retention, PITR, and checksums are operator responsibilities).
2. Supply a non-superuser migration credential with `CREATEROLE` plus `CREATE` on the target database, and a distinct bounded runtime login. Construct `PostgresStoreConfig::new(migrator_url, runtime_url, schema)`. The adapter validates the runtime login attributes and grants only generated-role membership.
3. Back up the database, including `store_identity`, `store_metadata`, and migration ledger. Restores must preserve cursor/receipt keys. Never bring a writable restore online beside its source without intentionally changing authority identity and revoking old credentials.
4. Open the adapter during readiness. Any migration checksum/catalog/policy/index drift is a hard failure; repair through a reviewed migration, never by editing the ledger.
5. Monitor pool saturation, the five-second transaction statement/lock watchdogs, serialization/deadlock errors, outbox age, receiver leases, audit/snapshot growth, backups, and PostgreSQL recovery/read-only status.
6. Shutdown stops claims at the runtime owner and closes only that adapter pool. Independent stores/pools remain valid.
7. Set `SMESH_A2A_DURABLE_BACKEND=postgres`, distinct TLS `SMESH_A2A_POSTGRES_MIGRATOR_URL` and `SMESH_A2A_POSTGRES_RUNTIME_URL`, `SMESH_A2A_POSTGRES_SCHEMA`, mandatory `SMESH_A2A_QUOTA_POLICY_PATH`, and an optional validated `SMESH_A2A_REPLICA_ID`. Authentication plus authorization policy and loopback durable mode are mandatory. Mixed SQLite/PostgreSQL configuration, a missing quota policy, or distributed quota configuration with SQLite is rejected before listener/database/runtime acquisition.

Migration leadership is transaction-scoped: any replica may take the advisory migration lock, but readiness is published only after both revisions and the exact catalog validate. Cut over explicitly after backup and quiescing SQLite writers; there is no automatic SQLite-to-PostgreSQL data migration.

Local verification:

```sh
export SMESH_TEST_POSTGRES_SUPERUSER_URL='postgresql://postgres:<fixture-password>@127.0.0.1:55432/smesh_test'
export SMESH_TEST_POSTGRES_ADMIN_URL='postgresql://smesh_migrator:<migrator-password>@127.0.0.1:55432/smesh_test'
export SMESH_TEST_POSTGRES_RUNTIME_URL='postgresql://smesh_test_runtime:<runtime-password>@127.0.0.1:55432/smesh_test'
export SMESH_POSTGRES_TEST_REQUIRED=1
cargo test --locked --test postgres_store -- --test-threads=1
cargo test --locked --test postgres_multi_replica -- --test-threads=1
```

Tests create random isolated schemas/roles, wrap each PostgreSQL test in a 30-second watchdog, and remove managed objects. If the migrator URL is absent they print an explicit skip unless `SMESH_POSTGRES_TEST_REQUIRED=1`.
